本单只升级 QMT Python 目录中的 `bigqmt_signal_trader` 桥接包，目标版本为
`0.3.56`。不部署交易策略，不修改 `machine.local.json`、Fact Secret、授权 Key、
QMT 登录凭据、Redis 配置或任何订单。

必须保留本项目的本地执行保护：账户绑定、本地授权和策略归因撤单。不要从上游仓库
直接覆盖整个 QMT `python` 目录。


## 1. 停止两个 Bridge

在模拟和正式 QMT 中停止 `BIGQMT_BRIDGE`。不要关闭 QMT、Redis 或托盘；不要启动
`BIGQMT_REDIS_DRYRUN`，更不要操作任何交易策略或订单。

## 2. 只同步桥接升级提交

```powershell
cd E:\kitling_QMT_work\kitling_bigqmt
git status --short
git fetch origin
git pull --ff-only origin <本机 host 分支>

# 若本机还没有受保护的 0.3.54 基础包，先带入它。
git merge-base --is-ancestor bd172f8 HEAD
if ($LASTEXITCODE -ne 0) { git cherry-pick bd172f8 }

# 0.3.54 -> 0.3.56 的上游 Bug 修复。
git merge-base --is-ancestor cd269e3 HEAD
if ($LASTEXITCODE -ne 0) { git cherry-pick cd269e3 }
```

不得 merge 整个 `feature/nas-private-config` 分支。若 cherry-pick 出现冲突：立刻停止，
不要用 `ours`/`theirs` 强行解决，不要提交冲突状态；把 `git status` 和冲突文件名回报 `.105`。

## 3. 本地测试

预期全部通过。本步骤不访问 QMT，不产生订单。

## 4. 自动备份并升级两套 QMT

```powershell
.\scripts\apply_xtquant_big_convert_candidate.ps1 `
  -CandidatePackage .\staging\qmt_bridge_simulation\bigqmt_signal_trader `
  -SimulationPythonDir 'E:\国金QMT交易端模拟\python' `
  -ProductionPythonDir 'E:\国金证券QMT交易端\python' `
  -BackupRoot 'E:\kitling_QMT_work\backups\bridge' `
  -ConfirmDeploy
```

脚本必须显示 simulation 与 production 均升级到 `0.3.56`，并打印各自的备份目录。
它只复制桥接包；不会启动或重启 QMT、Redis、托盘、Bridge 或策略。

## 5. 运行并只读验收

分别在模拟与正式 QMT 中运行 `BIGQMT_BRIDGE`，然后执行：

```powershell
py -3.12 .\scripts\check_bridge_ping.py --profile simulation --timeout 8
py -3.12 .\scripts\check_bridge_ping.py --profile production_readonly --timeout 8
```

两条均应为：`status=PASS`、`version=0.3.56`、`broker_call_made=false`、
`order_capability=false`。这是只读 Ping。

正式 profile 若显示 `allow_order_methods=false`，表示本机运行期开关仍锁定；代码能力已经部署，
无需将来再次升级 Bridge 包。
