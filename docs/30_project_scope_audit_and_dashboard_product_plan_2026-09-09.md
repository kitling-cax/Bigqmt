## 二、P18：Dashboard 产品研发

### 产品边界

- 默认只读；不提供下单、撤单、订单确认、Redis 写入或 QMT 写入端点；
- 模拟和正式只读使用隔离 profile、状态库和 URL，页面不得混合两个账户事实；
- 默认只监听 `127.0.0.1`；远程查看只在 P21 采用明确授权的只读网关后开放；
- QMT 是账户、持仓、委托、成交的事实来源；SQLite 是策略归属/NAV/审计事实来源；
- 数据缺失显示“未采集/等待交易时段/陈旧”，不伪造为错误或正常。

### 六个可访问的专门页面

| 路由视图 | 展示重点 | 首版验收 |
|---|---|---|
| `overview` | 环境、QMT/Bridge/Redis、资产摘要、订单锁、下一门禁 | 点击可进入独立路由；显示快照时间和健康状态 |
| `strategies` | 策略池、袖套初始资金、现金、持仓、NAV、收益率、曲线 | A 股/ETF 策略可筛选；外部基线不归属策略 |
| `account` | 账户资产、现金、持仓、证券名称/代码、可用数量、成本、市值 | 模拟/正式只读数据严格隔离 |
| `orders` | 委托、成交、拒绝原因、订单生命周期、归属策略 | 无写操作；空数据明确显示“暂无委托/成交” |
| `market` | QMT 行情、Redis、数据湖输出的新鲜度/延迟/缺失证券 | 非交易时段显示等待状态，不标为故障 |
| `audit` | 对账、重启、风控拒绝、运行日志、数据导出结果 | 可按时间/环境/策略筛选，支持定位证据文件 |

实现可以使用一个前端应用，但必须拥有可分享、可刷新、可测试的六个路由；不能再以单页滚动替代页面导航。首版路由方案在开发时确定为 `/simulation/<view>`、`/production-readonly/<view>` 或等价 hash 路由，并为浏览器前进/后退提供一致状态。

### 子阶段与依赖

1. `P18.1`：信息架构、路由模型、模拟/正式 profile 切换与只读权限模型；
2. `P18.2`：账户、持仓、委托/成交、行情、审计 API 投影，补齐时间戳和数据状态；
3. `P18.3`：策略袖套 NAV、收益归因和曲线（只统计已归属成交）；
4. `P18.4`：六页 UI、空状态、等待交易时段状态、移动端与白底主题；
5. `P18.5`：浏览器路由、刷新、键盘导航、模拟/正式隔离、无写端点自动化验收；
6. `P18.6`：由 BigQMT Tray 打开指定环境和指定页面。

P18 不会阻塞当前 `P12` 的模拟单笔验证，但 P14 Tray 的“打开 Dashboard”会先打开 P18.1 之前的单页只读版；P18 完成后再切换到指定路由页。
