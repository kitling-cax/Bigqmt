# .125 / .113：BigQMT Bridge 0.3.54 升级执行单

本单只升级 `bigqmt_signal_trader` 桥接包。它不部署任何交易策略、不改本机
`machine.local.json`、Fact Secret、授权 Key、QMT 登录凭据或 Redis 配置。

升级来源是 GitHub 提交 `bd172f8`：`feat: upgrade protected BigQMT bridge to 0.3.54`。
不要整分支合并 `feature/nas-private-config`，因为它与各 Host 的托盘分支有历史冲突；
只 cherry-pick 此一个提交。

## 适用目录

两台 Host 都使用：

```text
项目根目录: E:\kitling_QMT_work\kitling_bigqmt
模拟 QMT:   E:\国金QMT交易端模拟\python
正式 QMT:   E:\国金证券QMT交易端\python
```

## 1. 停止桥接策略

在两个 QMT 客户端中停止 `BIGQMT_BRIDGE`。只停止桥接策略，不关闭 QMT、Redis、
托盘，也不操作任何交易策略或订单。

## 2. 获取受控升级提交

`.125` 在 `host/125/structure` 分支执行；`.113` 在 `host/113/structure` 分支执行。

```powershell
cd E:\kitling_QMT_work\kitling_bigqmt
git status --short
git fetch origin
git pull --ff-only origin <本机 host 分支>
git cherry-pick bd172f8
```

若 cherry-pick 冲突：停止，不要用 `--strategy ours` 或整分支 merge；把冲突文件名和
`git status` 回报给 `.105`。不得提交包含本机配置、密钥、日志、数据库或策略内容的文件。

## 3. 本地编译与测试

```powershell
py -3.12 -m pytest -q
```

预期：全部通过。此步骤不连接 QMT、不发订单。

## 4. 自动备份并覆盖两个 QMT 桥接包

```powershell
.\scripts\apply_xtquant_big_convert_candidate.ps1 `
  -CandidatePackage .\staging\qmt_bridge_simulation\bigqmt_signal_trader `
  -SimulationPythonDir 'E:\国金QMT交易端模拟\python' `
  -ProductionPythonDir 'E:\国金证券QMT交易端\python' `
  -BackupRoot 'E:\kitling_QMT_work\backups\bridge' `
  -ConfirmDeploy
```

脚本会先分别完整备份两个旧包，再覆盖包文件；不会启动 QMT、Redis 或策略，也不会改本机
配置。输出必须显示 simulation 与 production 均升级至 `0.3.54`。

## 5. 启动并做只读验收

分别在模拟与正式 QMT 中重新运行 `BIGQMT_BRIDGE`，不要同时运行
`BIGQMT_REDIS_DRYRUN`。随后执行：

```powershell
py -3.12 .\scripts\check_bridge_ping.py --profile simulation --timeout 8
py -3.12 .\scripts\check_bridge_ping.py --profile production_readonly --timeout 8
```

两条均应为 `status=PASS`、`version=0.3.54`，并且
`broker_call_made=false`、`order_capability=false`。这是只读 Ping，不构成下单测试。

正式 profile 可能显示 `allow_order_methods=false`：这表示本机运行期开关仍锁定；桥接代码的
未来下单能力已随同一套代码部署，不需要为将来再升级桥接包。
