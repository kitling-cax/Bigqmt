# `.125` / `.113` Host 修复发布说明（2026-09-19）

本说明对应提交 `fix: repair host fact identity redis paths and deterministic trays`。
两个策略运行主机应从各自的 host 分支同步本提交后，在本机编译并做本机验证。

## 已修复

### P1：Fact Secret 与本机 host_id 不一致

- `deliver_fact_outbox.py` 新增 `--expected-host-id`。
- 托盘投递 Fact 时会把本机 `machine.local.json` 的 `host_id` 传入。
- Secret 中的 `host_id` 不一致时，在本机拦截，不向 Coordinator 发送错误事实；状态显示为“Fact Secret 不匹配”。
- 该修复不会修改或打印 Secret。每台主机仍必须使用独立、按真实 host_id 签发的 Fact Secret。

本机处理顺序：

1. 停止托盘。
2. 核对 `config/machine.local.json` 的 `host_id`。
3. 删除错误的本机 Fact Secret，按本机 host_id 重新签发并部署。
4. 清理或保留 Outbox 均可；重新启动托盘后观察 `host_fact_delivery` 是否 ACK。
5. 只有看到 Shadow Coordinator 返回 200/ACK，P1 才算完成。

### P2：正式 Redis 运行目录

`config/redis/redis-production.conf` 已统一使用：

```text
runtime_data/redis/production_readonly/
```

托盘启动 Redis 前会从模板生成本机 `runtime_data/redis/<profile>/redis-autostart.conf`，并把项目根转换为 MSYS 路径。旧的 `runtime_data/redis/production/` 临时目录不再作为正式配置依据。

### P4：v1.1.15 日报和模拟周期账户绑定

- 日报脚本、周期执行脚本从 `host_gateway.simulation.json` / `machine.local.json` 读取账户。
- 不再把日报固定写入合成测试账户。
- 本机账户未配置时直接阻断，不猜测、不下单。

### P5：托盘 EXE 可重复构建

`scripts/normalize_native_pe.py` 在编译后固定 PE COFF 时间戳和 .NET MVID；`build_native_account_trays.ps1` 自动调用它。

构建验证：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build_native_account_trays.ps1
Get-FileHash tray\BigQMT_Simulation.exe,tray\BigQMT_Production_ReadOnly.exe -Algorithm SHA256
```

同一源码、同一编译器和同一图标输入下，两次构建应得到相同 SHA-256。编译器 warning（不可达分支）不影响本次修复。
