# P04 行情连续性与 P05 恢复演练

时间：2026-09-08 10:05（Asia/Shanghai）  
环境：模拟 BigQMT；只读 Redis RPC；订单接口关闭。

## 模拟 QMT / 策略桥接重启实测

模拟 QMT 已是本次新启动的客户端进程（约 10:14），因此没有强制结束正在运行的客户端。`BIGQMT_REDIS_DRYRUN` 随后已重新初始化，Redis RPC 服务恢复监听 `bigqmt:rpc:queue:90000001`，且 `allow_order_methods=False` 保持不变。

主机侧随即执行 `scripts/run_recovery_reconcile.py` 并通过：重新读取 QMT 的账户事实后，持仓数量无差异，委托和成交均为 0。本地 SQLite 只保存本次核对快照，未以旧状态回写或替代 QMT 事实。Redis 服务中断后的恢复演练尚未执行。

## P04：连续行情采集

新增有界采集器 `scripts/run_readonly_collector.py`。每轮均：

1. 写入仅表示主机存活的 Redis 心跳；
2. 读取账户、持仓、委托、成交和持仓标的行情；
3. 写入独立 SQLite WAL 快照与 JSONL 审计；
4. 逐标的保存券商事件时间、主机接收时间、计算年龄和新鲜度状态。

三轮、两秒间隔的实测均完成，单轮耗时约 2.4–2.9 秒，且无订单或成交。

数据质量结果不能整体标为通过：`511010.SH`、`511990.SH`、`513500.SH`、
`518880.SH` 的行情年龄为约 1–6 秒；`513100.SH` 的 QMT 时间停在 09:15，
在采集时已约 50 分钟陈旧。

因此新增 `scripts/report_quote_gate.py`。它在最新快照上按默认 180 秒门限返回：

- `allowed`：可被后续策略和数据湖消费者使用；
- `blocked`：不得进入策略估值、信号或下单规划；
- 不做静默第三方数据源回退。

P04 保持 `IN_PROGRESS`，待定位 `513100.SH` 行情陈旧原因并验证断连/重连。

## Redis 中断、恢复与行情恢复实测（10:30–10:32）

在确认 `127.0.0.1:6379` 是本项目专用模拟 Redis（配置、F 盘持久化目录及客户端均为
BigQMT DB 5）后，执行了一次受控 Redis 重启。重启后的 Redis 从本项目 AOF 成功恢复并重新
监听本地端口；模拟 QMT Bridge 随后无需重启即重新响应只读 `ping` 与 `get_full_tick`。

此前停在 09:15:01 的 `513100.SH` 也恢复为正常快照：10:31:01 起 `stockStatus` 观察值为
`3`、五档盘口非零、成交量和成交额持续增长。五次、两秒间隔的只读诊断中，5 个 ETF 均在
180 秒门限内，行情门禁无被拦截标的。原始证据位于：

`runtime_data/evidence/simulation/qmt_quote_health_after_redis_recovery_2026-09-08_1031.json`

随后三轮主机采集和一次 QMT 权威事实对账均通过：5 个账户持仓数量无差异，委托和成交仍为
0，订单权限保持关闭。此前陈旧的直接根因尚不能仅凭本次样本断言；当前结论是其与 Redis /
桥接实时链路恢复同时消失。P04 仍需在交易时段完成更长时间的稳定性采样，才可关闭。

## 长时采样的超时处理修正（10:49）

首次 30 分钟采样在运行中遇到一次只读 `get_full_tick` 超时而提前结束。这一异常保留为 P04
证据，不能计为通过。采样脚本已改为每一轮立即写入当前报告；超时会以 `ATTENTION` 样本保存并
继续下一轮，绝不以旧行情或第三方数据补齐。短时回归采样通过后，已启动使用该机制的第二次
30 分钟采样。

## P04 长时稳定性采样通过（10:50–11:20）

第二次采样以 30 秒间隔完成 61 个样本；5 个 ETF 在全部样本中均通过 180 秒新鲜度门限，未出现

`runtime_data/evidence/simulation/qmt_quote_health_30m_retry_2026-09-08_1050.json`

## P05：主机恢复对账

新增 `scripts/run_recovery_reconcile.py`。它将 SQLite 最近快照视为历史证据，
而非覆盖来源；每次恢复都重新向 QMT 查询券商事实，再保存一轮新快照并比较持仓数量。

实测结果：恢复前后 5 个持仓数量一致、委托和成交均为空、对账记录已写入 SQLite
及 JSONL。该结果仅代表主机侧进程恢复演练通过；QMT/Redis 被中断后的恢复仍待单独测试。
