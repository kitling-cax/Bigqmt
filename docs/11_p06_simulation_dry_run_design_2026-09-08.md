# P06 模拟订单 Dry-run 设计（候选，未启用）

状态：`CANDIDATE`。本文件只定义下一阶段的本地验证边界；不部署到 QMT，不打开订单
RPC，也不构成任何模拟或正式盘下单授权。

## 目标

在 v1.1.15 信号接入前，先验证“信号 → 目标仓位 → 订单意图”的可审计路径。输出是本项目
SQLite WAL 与 JSONL 审计中的**拟订单**，不是 QMT 委托。

## 固定安全开关

- 环境必须是 `simulation`；正式环境一律拒绝。
- `orders_enabled` 必须为 `false`；若为 true，Dry-run 直接失败关闭，不尝试发送。
- 仅接受最新 QMT 行情门禁为 `ALLOWED` 的标的；缺行情、超时、陈旧或来源冲突均拒绝生成意图。
- 仅使用 Host Gateway 的只读账户、持仓与行情事实；不得向 Redis 队列提交 `order_stock`、
  `cancel_order_stock` 或等价命令。

## 订单意图合同

每个意图必须含 `schema_version`、全局唯一 `request_id`、`strategy_id`、`signal_id`、环境、
标的、买卖方向、目标数量、拟价、引用的行情快照/事件时间、产生时间和风险决策。拟价必须为
正数；买入必须给出策略袖套可用现金和预计费用，卖出必须同时通过策略归属数量及 QMT 可卖数量。
`quote_admission`、`preflight_admission`、`parity_admission` 均须为 `ALLOWED`。

同一 `request_id` 重放必须返回同一条本地记录；若载荷不同，视为幂等冲突，阻止后续操作。
Dry-run 状态只允许：`PLANNED`、`BLOCKED`、`DUPLICATE`、`EXPIRED`，不得出现“已报”“已成”等
券商状态。

## v1.1.15 首期限制

- 只允许 ETF 策略袖套 `S10_D1_U25_NO_ALCOHOL_5D_SIM_MAIN_V1_1_15`；初始资金 100,000 元，资金与收益只在该袖套内核算。
- 每次只允许一个目标标的；买入数量必须为 100 份整数倍，策略资金使用上限与价格保护沿用
  已冻结的 v1.1.15 规则。
- Dry-run 只验证数量、资金、可卖数量、行情门禁和幂等；不修改信号公式、证券池或换仓规则。
- 账户既有持仓不自动归属该策略。拟卖出必须先能证明策略归属与 QMT 可卖数量。

## P06 进入条件与验收

进入条件：P04 的长时行情稳定性采样通过，P05 的 QMT/Redis 恢复证据完整，且用户确认开始
Dry-run 实现。

验收至少覆盖：有效买入计划、资金不足、非整手、行情陈旧、可卖不足、重复请求、同 ID 载荷
冲突、进程重启后重放。所有用例均不能产生 QMT 委托。只有 Dry-run 验收和用户对“极小规模
模拟真实下单”的单独确认完成后，才可讨论 P06 的下一小步。

此结果仅完成 P06 的本地 Dry-run 子步骤，不是券商委托、不是成交，也不授权后续真实模拟盘下单。

## 离线 Dry-run 门禁补全（2026-09-08 20:xx）

本地规划器已补充拟价/费用、策略袖套现金、策略归属卖出数量、券商可卖数量、运行时预检和
策略 parity 的失败关闭检查。该代码没有 QMT、Redis 或订单接口依赖；当前 P06 parity 为
`BLOCKED` 时，`parity_admission=BLOCKED` 会拒绝任何拟订单记录。

`scripts/run_dryrun_from_json.py` 是唯一离线运行入口。它不信任输入 JSON 中的环境、订单开关、
预检或 parity 字段，而是从 `progress/current_status.json` 强制读取项目门禁；缺少任一门禁字段
时默认 `BLOCKED`。该脚本不导入 QMT RPC，输出只会是本地 `RECORDED`、`DUPLICATE` 或 `BLOCKED`。

## PTrade v1.1.15 复现基线

本项目不把 v1.1.15 重新解释为简化的“目标仓位输出”。唯一权威来源是 PTrade 原始源码及其
长期回测导出；源码 SHA-256、U25 标的池、动量/风控/时序/账本规则与 QMT 验收顺序已冻结到
`strategy_baselines/s10_d1_v1_1_15_ptrade.json`。QMT 侧只能从该基线复现；任何规则变化必须
创建新版本，不能借迁移之名修改 v1.1.15。
